# Adflow — 가게 정보와 한 줄만 넣으면 마스코트 네컷 광고가 나온다

코드잇 AI 고급 프로젝트 3팀 (김범진, 강지연, 김효섭, 유재열, 전재완) · github.com/beomjin2/Adflow · 2026-09-30 main 기준

## 한눈에 보기

| 구분 | 내용 |
|---|---|
| 푸는 문제 | 사장님에게는 광고를 배울 30분이 없다 |
| 만든 것 | 알릴 내용 한 줄 → 마스코트가 요즘 밈으로 말하는 네컷 만화 → 인스타그램 게시 |
| 핵심 기술 1 | 사장님의 평문을 검증된 Danbooru 태그로 바꾼다 |
| 핵심 기술 2 | 캐릭터는 품질 모델, 네컷은 속도 모델로 나눠 쓴다 |
| 핵심 기술 3 | IP-Adapter 구간 제어로 네 컷 내내 같은 캐릭터를 유지한다 |
| 핵심 기술 4 | 밈을 상황별로 분류하고, 이 가게에 맞는 밈을 골라 준다 |
| 비용과 속도 | 광고 1건 GPT 비용 **약 0.5원**, 네컷 한 편 **약 110초** |

## 1. 왜 만들었나

| 지표 | 숫자 | 설명 |
|---|---|---|
| 디지털 활동을 전혀 안 하는 소상공인 | 72.8% | 광고를 안 하는 사장님이 다수 |
| 안 하는 이유 1위 "인력·지식 부재" | 45.6% | 자금 부족은 21.5%. 돈이 아니라 사람과 시간 |
| 1인 사업체 | 79.9% | 광고를 배울 30분이 없다 |
| 음식점 주당 근무시간 | 53.5시간 | 같은 근거 |
| 전국 제과점 | 24,638개 | 도메인을 빵집으로 |
| "오늘 상황 → 오늘 홍보 이미지"를 잇는 빵집 소프트웨어 | 4종 중 0종 | 시장의 빈칸 |
| 두쫀쿠 유행 때 빵집 매출지수 | 100 → 350 | 트렌드·SNS가 매출을 흔든다 → 밈을 광고에 |

그래서 **사장님이 입력하는 것은 이야기 한 줄뿐**이다. 그림 · 구도 · 말풍선 · 유행 밈은 서비스가 뒤에서 한다. 마스코트 캐릭터(사람 그림의 거부감 없음) · 네컷 만화(캐러셀은 여러 장) · 유행 밈(사장님이 밈을 몰라도 "요즘 말"로)을 택했고, 그 대가로 생긴 기술 결정 여섯 가지가 3절이다.

## 2. 무엇을 만들었나 — 여섯 화면

| 순서 | 화면 | 사장님이 하는 일 |
|---|---|---|
| 1 | 가게 등록 | 가게 정보 입력. 처음 한 번만 |
| 2 | 마스코트 | • 대화로 캐릭터 시트 **7칸** 채우기<br>• 후보 **3장** 중 하나 확정 |
| 3 | 트렌드 | • 요즘 밈 목록 보기<br>• "밈 추천받기"로 밈 **3개**를 이유와 함께 받기 |
| 4 | 광고 만들기 | • 알릴 내용 한 줄 입력<br>• 서비스가 쓴 스토리 승인 |
| 5 | 네컷 그리기 | 승인한 스토리대로 네 컷 생성 |
| 6 | 완성과 게시 | 확인 후 인스타그램 게시 |

- 앞 단계가 끝나야 다음 화면이 열린다
- 그림은 스토리 승인 뒤에만 그린다 → 다시 만들어도 비용은 원 단위

| 영역 | 기술 |
|---|---|
| 화면 | React |
| 서버와 DB | FastAPI, SQLite |
| 그림 생성 | ComfyUI, Anima |
| 글과 대화와 추천 | OpenAI (GPT, 임베딩) |
| 유행 측정 | 네이버 데이터랩 검색어 트렌드 API |
| 장비 | GCP L4 GPU 서버 1대 |

## 3. 핵심 기술 — 어떻게 했고, 숫자는 어떻게 나왔나

### 결정 1. 사장님 말 → Danbooru 태그

GPT가 태그 후보를 만든다 → 코드가 Danbooru 태그 사전(159만 행)에서 찾는다 → 2,000장 이상 쓰인 일반 태그만 쓴다.

| 지표 | 숫자 |
|---|---|
| 쓸 수 있는 태그 | 6,340개 |
| 사전에 없던 팀 태그 | 11개 → 0 |
| 남의 캐릭터 · 작품 · 작가 태그 | 2,070개 → 0 |

### 결정 2. 태그 구조

네 컷 공통 태그(캐릭터)와 컷마다 바뀌는 태그(구도 · 장면)를 나눠 넣는다.

| 층 | 내용 | 예 |
|---|---|---|
| 전역 | 스타일 | masterpiece, (chibi:1.3) |
| 캐릭터 | 외형 · 옷 · 나이 | dog, brown_fur, yellow_apron |
| 구도 | 샷 크기 · 앵글 · 인원 · 시선 | upper_body, from_side, solo |
| 장면 | 표정 · 동작 · 장소 · 소품 · 빛 | smug, holding_tray, shop |

### 결정 3. 그림 모델

API 이미지 모델 대신 자체 GPU에서 도는 디퓨전 모델을 쓴다. 장당 API 비용 없이 서버 1대로 돌고, 참조 그림(IP-Adapter)과 태그 검증을 직접 걸 수 있다.

| 후보 | 크기 | 판단 |
|---|---|---|
| **Anima · 채택** | 2B DiT | Danbooru 태그 + 자연어로 학습. L4 24GB 1장 · RAM 15GB에서 돌고, 12스텝 Turbo 변형과 전용 IP-Adapter 노드가 있다 |
| Qwen-Image-Edit | 22.6GB | 4컷 행동 100% · 소품 100%로 품질은 더 좋았으나, RAM 15GB VM이 3번 멈춰 폐기 |

| 용도 | 모델 | 왜 |
|---|---|---|
| 캐릭터 후보 3장 | Anima aesthetic v1.1 · 30스텝 · cfg 5 | 사장님이 한 번만 고르는 그림이라 품질 우선. cfg 5라 사람 · 노출 차단 프롬프트가 듣는다. 1장 56초여도 한 번뿐 |
| 네컷 | CapAnima Turbo 1.1 · 12스텝 · cfg 1 | 매번 네 장을 그리니 속도 우선. 컷당 35.4초 → 8.7초(3종 36장 비교). nginx 60초 한도 안에 든다 |

**속도 — 무엇을 바꿔서 얼마나 빨라졌나**

| 무엇 | 전 | 후 | 바꾼 것 |
|---|---|---|---|
| 캐릭터 후보 3장 | 168초 | **86초** | 1장씩 3번 → 한 번에 배치 생성 |
| 네컷 컷당 | 35.4초 | **8.7초** | Anima base 30스텝 → Turbo 12스텝 |
| 태그 사전 읽기 | 66.6초 (502 오류) | **8.9초** | 요청마다 읽기 → 서버 시작 때 한 번 + 잠금 |
| 스토리 씨앗 3개 | 15초 | **5초** | 순차 생성 → 병렬 생성 |
| 밈 추천 응답 | 10초 초과 | **수 초** | gpt-5-mini 추론 강도 기본 → 최소 |
| 네컷 한 편 | — | **약 110초** | 실제 API 순서 |

### 결정 4. 네 컷 내내 같은 캐릭터

확정한 마스코트 그림 1장을 참조(IP-Adapter)로 넣는다. 앞 30% 스텝은 끄고 뒤에만 켠다.

| 지표 | 숫자 |
|---|---|
| 시킨 행동 · 소품이 나온 비율 | 9% → 41% |
| 캐릭터 특징 4개 유지 (4점 만점) | 1.38 → 2.62 |
| 기준 그림과 닮은 정도 (DINOv2) | 0.678 → 0.833 |

### 결정 5. 만화답게 — 컷마다 구도를 다르게

- 컷마다 GPT가 구도를 정한다. 캐릭터를 얼마나 크게, 어느 각도에서, 어느 쪽에 둘지, 어디를 볼지
- 말풍선은 GPT가 비워 둔 쪽에 넣는다

| 지표 | 숫자 |
|---|---|
| 캐릭터가 좌/우에 놓여 말풍선 자리가 생긴 컷 | 12컷 중 9컷 |
| 정면이 아닌 각도로 그려진 컷 | 12컷 중 7컷 |
| 모델이 그린 간판과 겹치지 않은 컷 | 17컷 중 12컷 |

### 결정 6. 밈 — 묶고, 나누고, 고른다

| 단계 | 어떻게 | 핵심 수치 |
|---|---|---|
| 같은 밈 묶기 | • 이름 유사도 + 유래 유사도 (TF-IDF, 0~1) | • 이름 유사도: 같은 밈 **0.491** / 다른 밈 **0.003**<br>• 중복 처리해서 31건 → **25건** (정답 7쌍 전부, 잘못 묶음 0) |
| 상황 분류 | • 밈 글을 임베딩으로 바꿔 상황 **6개** 중 가장 닮은 곳에 넣는다 (코사인 유사도) | • 가장 닮은 상황과의 유사도 **0.206~0.530** (중앙 0.330)<br>• **0.228** 미만이면 미분류 → 2건 (0.225, 0.206)<br>• 25건 → 재미 **16** · 기다림 **3** · 전후 **3** · 감탄 **1** · 미분류 **2** |
| 유행 판정 | • 검색량 평소의 **3배** = 유행<br>• 끝이 수집일 **3일** 안 = 유행 중 | • 25건 중 **20건** |
| 추천 | • 상황 **1개** → 밈 **3개** | • 10초 → **수 초** |

## 부록. 용어

| 용어 | 뜻 |
|---|---|
| Danbooru 태그 | 애니 그림 모델이 학습한 영어 키워드. 한국어 문장보다 이 태그를 훨씬 잘 알아듣는다 |
| 태그 사전 | Danbooru 태그 159만 행 목록. 태그마다 쓰인 그림 장수가 적혀 있다 |
| 태거 | 그림을 보고 거꾸로 태그를 붙이는 모델(wd-vit-tagger-v3). 채점과 간판 검사에 쓴다 |
| IP-Adapter | 참조 그림 한 장을 보고 닮게 그리게 하는 장치 |
| 임베딩 | 글을 숫자 벡터로 바꾼 것. 뜻이 비슷하면 벡터도 가깝다 |
| DINOv2 | 그림을 숫자 벡터로 바꾸는 모델. 피사체의 생김새 비교에 흔히 쓴다 |
| 코사인 유사도 | 두 벡터가 얼마나 같은 방향인지. 똑같으면 1, 관계없으면 0 |
| TF-IDF | 글자 조각의 빈도로 두 글의 유사도를 재는 방법 |
